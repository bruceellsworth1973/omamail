# IMAP, SMTP and Proton Bridge

Required when touching native IMAP/SMTP transport, IMAP parsing, listing, paging or mutations.

- Loopback connections, including custom Proton Bridge ports, upgrade with STARTTLS before authentication; 993/465 use implicit TLS. `insecure` permits a self-signed certificate only on loopback, never plaintext or downgrade after failed STARTTLS. Remote connections use STARTTLS on standard STARTTLS ports and implicit TLS otherwise, with certificate verification. Plaintext synthetic peers require `testPlaintext` compiled only for tests or `integration-test-credentials`.
- `Imap.js` owns protocol strings/parsing; RFC 822 formatting belongs to the message module. The legacy `scripts/mail-transport.sh` carries base64 fields over stdin and passes curl config over stdin. Follow [security boundaries](../SECURITY-BOUNDARIES.md); base64 does not validate config values.
- Keep responses byte-preserving: IMAP literal lengths count octets, not UTF-8 characters. The legacy base64 transport preserves that distinction.
- UID order is not arrival order: Bridge can assign imported mail UIDs newest-first. Snapshot UIDs with `UID FETCH 1:* (UID)`, fetch INTERNALDATE in explicit batches of at most 4096, search stable UID windows, and sort by date before paging. Descending UID is only a date tie-breaker. Do not settle a newest prefix from a high-UID window or substitute shifting sequence-number windows. Unsolicited UID/FLAGS updates must preserve known dates.
- Use `BODY.PEEK`, not `BODY`, for reads that must not mark mail seen.
- Use `UID EXPUNGE`, never bare `EXPUNGE`, which also deletes messages marked by other clients.
- IDs are `<uid>:<folder>`; UIDs alone collide across folders.
- Discover folders with LIST and SPECIAL-USE; do not guess localized/provider-specific names.
- Undo places (`mail.locate`/`mail.place`, `src/providers/imap/place.rs`) are `{"folder", "messageId"}`: the folder as LIST spells it (non-empty, at most 4096 bytes, no control characters) and the Message-ID header, printable ASCII up to 998 bytes, or `""` when the message has none usable. Locate EXAMINEs each folder once and fetches `UID FLAGS BODY.PEEK[HEADER.FIELDS (MESSAGE-ID)]`; a UID or folder that is gone is `undo_message_lost`. Place reads LIST once (a destination that is not a selectable folder is `undo_folder_gone`), then per source folder SELECTs once (EXAMINE when nothing moves), fetches the same header to prove each UID still names the recorded message (a different Message-ID is `undo_message_lost`), clears `\Deleted` on messages leaving the trash as `imap.untrash` does, and moves with one UID MOVE per destination, or UID COPY, `\Deleted` and UID EXPUNGE of those UIDs without MOVE. The new UID comes from COPYUID; without it the destination is EXAMINEd and searched with `UID SEARCH HEADER MESSAGE-ID`, from the UIDNEXT read before the move when the server lacks UIDPLUS, taking the highest match. A message already in its folder is answered with its own id and nothing written.
- Undo is not exact when: a message has no usable Message-ID and the server sends no COPYUID (it moves, but is `undo_message_lost` and cannot be followed further); a moved message's Message-ID is shared by another message that arrived in the destination at the same time, or (with UIDPLUS but no COPYUID) by an older one with a higher UID; `\Deleted` cleared when leaving the trash is not set again when it goes back; the COPY fallback is interrupted after COPY (the message is then in both folders, and the item fails with `imap_command_failed`); and a folder was deleted and recreated under the same name (it is used as the same folder). Keywords and other flags travel with the message.
